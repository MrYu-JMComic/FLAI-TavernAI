# 状态栏模板事件与占位符校验修复计划

## 目标与范围

按用户追加要求完全取消状态栏自定义模板的内容校验，不再因标签、事件、JavaScript、CSS 或占位符语法阻止保存。修复原始 HTML 事件模板的运行时识别，复用现有运行时；在 AI 完善助手中增加当前草稿的状态栏预览按钮，保持普通模板的兼容行为。

## 执行任务

- [x] 定位报错来源，核对 AI 工具写入、模板识别与角色保存校验之间的差异。
- [x] 移除自定义模板的内容校验、错误列表与保存阻断，修复事件模板识别，清理相关旧逻辑。
- [x] 在助手中增加状态栏预览，复用现有预览组件，支持未保存草稿与本地交互。
- [x] 增加覆盖实际报错的回归验证，确认独立折叠、样式和占位符仍正常。
- [x] 执行相关测试、前端构建、编码及必要的完整审核，记录结果。

## 验收标准

1. AI 写入或手动输入包含 onclick 等事件的状态栏模板可以保存，并在现有运行时中正常交互。
2. 任意模板内容不会因内容语法或标签校验被拦截；JavaScript 中的花括号不参与变量推断或插值，实际模板占位符保持兼容。
3. 编辑、预览、保存再读取的行为一致；现有代码模式与普通模板不发生回归。
4. 保留工作区其他修改，不改动用户数据库或上传目录。

## 验证命令

- 后端：在 backend 执行 npm test；专项测试使用 FLAI_DB_PATH=:memory:。
- 前端：在 frontend 执行 npm run build、相关单元测试与 Playwright 回归。
- 全项目：node scripts/check-encoding.mjs、git diff --check；跨前后端或共享运行时变更时运行 powershell -ExecutionPolicy Bypass -File scripts/review-gate.ps1。
