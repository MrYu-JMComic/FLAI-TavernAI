# AI 角色卡与服务器草稿同步修正计划

## 目标

预览、AI 实际输入与保存角色必须使用同一份当前服务器会话草稿。历史版本提供“用已保存角色卡覆盖草稿”，以数据库正式卡完整替换草稿，清理旧运行状态，防止后续保存回滚正式卡。完全移除浏览器角色卡草稿内容的持久化，每次进入 AI 完善前清理遗留本地草稿，再加载服务器会话。

## 范围

- 状态栏预览恢复为当前草稿，清理预览正式卡的专用刷新逻辑。
- 以数据库正式卡覆盖当前会话草稿，替代方向错误的历史草稿写正式卡接口。
- 正式卡完整字段、状态栏、高级设置、头像、标签及世界书关联同步至草稿；旧计划、检查点、运行上下文与待应用修改清空。
- 手动编辑与 AI 完善复用同一个服务器会话存储；浏览器仅保留会话 ID 与偏好、布局设置。
- 覆盖前串行完成自动保存，保留原草稿历史；失败不清空当前输入。
- 历史弹窗保持窄屏可用，提供确认、进度、成功与重试反馈。
- 清理被替换的本地存储、交接载荷、旧 API、预览分支和过时测试。

## 验收标准

1. 预览显示当前会话草稿，AI 编辑和保存使用相同数据；打开预览不读取或修改正式卡。
2. 历史操作从数据库完整读取正式卡并覆盖当前草稿，正式卡、资产与世界书不被写入。
3. 原草稿保留为历史；旧计划、检查点、上下文、头像与世界书意图不可恢复到新草稿。
4. 覆盖后刷新、AI 下一次请求和保存角色均保持新内容，不回滚正式卡。
5. 服务器校验用户、角色、会话归属与运行锁；失败保持草稿可恢复，可重试。
6. 角色草稿内容不写入 localStorage 或 sessionStorage；每次进入 AI 前先清理旧草稿缓存，偏好和布局保留。
7. 手动编辑、进入 AI、返回编辑器与刷新复用服务器草稿；保存失败保留输入并阻止显式交接丢失。
8. 历史弹窗桌面及 360px/730px 窄屏无横向溢出。
