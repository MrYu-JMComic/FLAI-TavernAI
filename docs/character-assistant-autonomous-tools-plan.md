# 角色助手自主对话与工具循环优化计划

## 目标

参考 Codex 的工作方式，允许角色助手在一个会话中自主判断是否需要工具、一次调用一个或多个工具、根据工具结果继续调用或直接回复。服务端保留权限、参数 Schema、用户可编辑范围、用户确认和最大总循环次数等边界，不再规定每一轮必须执行哪个工具或只能执行一个写入动作。

## 范围

- 调整角色助手系统提示词，让模型自行规划、检查结果、修正和收尾。
- 移除角色助手执行器对同轮写入、待处理工具顺序和“下一轮唯一动作”的强制拦截。
- 保留工具白名单、字段过滤、幂等提示、计划范围、`finish_character_draft` 验收和总循环上限。
- 让无工具自然语言回复成为正常结束状态；对话模式下不因没有工具调用而反复追加格式提醒。
- 优化工具过程数据与前端展示，显示每个模型步骤中的推理摘要、工具调用、返回结果和模型后续决定，不把轮次当成工作账本。
- 增加多工具同轮、多轮自主继续、无工具回答、提前完成和错误恢复测试。

## 验收标准

- 同一模型响应可成功执行多个互不冲突的角色工具，且每个工具结果都回传给模型。
- 模型可根据前一轮结果自主选择下一工具、重复修正或直接结束，不被 `pendingToolNames` 或 `ROUND_ACTION_LIMIT` 强制改道。
- 无工具的正常对话直接返回，不被无意义的“请调用工具”提示打断。
- 越权工具、未启用领域、非法参数、用户确认和总循环上限仍然有效。
- `finish_character_draft` 仍可作为写入任务的结构验收信号，但不会被固定到某个轮次。
- 前端轨迹准确显示实际调用数量、工具结果和失败信息，历史旧数据仍可展开。
- 后端测试、前端构建和编码检查通过。

## 执行记录

- `characterAssistant.js` 不再限制每轮写入数量，也不根据 `pendingToolNames` 队列拦截模型自主决定的工具顺序；新检查点将兼容字段保持为空。
- 对话助手的工具提示现允许模型自主选择工具、批量执行、根据结果修正或继续，并在写入后自然语言结束；`finish_character_draft` 仍可用于显式结构验收。
- 自由会话的工具结果不再把 `finish_character_draft` 暗示为强制下一步；已审批计划与传统生成仍按原验收要求结束。
- 非对话角色生成和已审批计划仍要求 `finish_character_draft`。已审批计划的步骤不可绕过，工具白名单、Schema、字段范围、用户确认、操作审计和 24 次总模型调用上限保留。
- 过程面板改为显示模型决策步骤和真实工具调用数，旧版限制错误保留可读标签。
- 后端助手定向测试 32/32、完整后端测试 1558/1558 通过；前端单元测试 133/133、端到端测试 53/53、生产构建、生产依赖审计、编码检查与 Git 差异检查通过。审核门禁 9/9 阶段通过。
