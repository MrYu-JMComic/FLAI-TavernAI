## 测试数据库隔离

2026-09-30 曾发现静态导入 `backend/src/db.js` 在模块载入时打开并迁移真实 `backend/data/flai.sqlite`。在测试正文里赋 `FLAI_DB_PATH` 来不及阻止静态 import；多个进程还可能竞态写入迁移账本。旧文档记录当时没有同日备份，不能通过重复运行已升级真实库证明旧版本升级安全。

当前代码已具备两层保护：

1. `backend/scripts/run-tests.mjs` 在启动子进程前设置临时 `FLAI_DB_PATH`，结束后清理临时目录；调用方显式设置的路径仍被保留，所以运行测试前不能把它指向真实库。
2. 测试创建独立数据库从 `db/runtime.js` 导入，不静态导入会打开 singleton 的 `db.js`；`testDatabaseIsolation.test.js` 检查启动器环境和静态导入。

新增迁移使用旧版本 fixture 的副本，验证空库、真实升级路径、重复执行、外键和失败回滚。`backend/data`、`backend/uploads` 与环境配置仍受 [AGENTS.md](../AGENTS.md) 保护；本文整理不对真实数据做恢复或迁移。启动前备份不能替代测试隔离。

## 会话记忆 V1 运维边界

2026-11-01 的角色工作流升级将默认同步方式调整为有边界的后台连续性，取代此前默认等待核心的约定；仍沿用隔离提案与规范原子提交，不恢复规则提取或工具立即写库。本页下方历史验证批次保留原文。

- 自动和公开记忆任务通过 `commitMemoryPacket` 接受隔离提案，人工审查在原事务追加规范修订。核心提交连同领域计划、来源证据、回执与派生 outbox 原子完成；模型失败不留半轮事实，取消/失败缺口不能由后续核心跳过。
- 默认 `background` 的 cast 模式允许必要核心排队、执行或可恢复失败时继续生成。上下文必须保留从最早未完成轮次到当前所选历史截止点的完整原文后缀，包括该轮用户消息、后续用户/助手消息、版本与附件；整个后缀受预算保护，已规范接受的前缀才可退出短期连续性。不能只截取最近几条消息而遗失较早积压。
- 后缀超过 `shortTermTurns` 时明确返回 `MEMORY_SHORT_TERM_CAPACITY`；受保护输入超过对话预算或模型窗口时也明确拒绝，均保留 `accepted:false` 与草稿/附件，不裁掉剧情再调用模型。历史处于需重建状态仍须恢复。显式 `blocking` 和严格 actor 模式继续在取得生成锁、保存用户输入之前等待必要核心；失败/超时保留输入。摘要和向量是独立派生工作，检查 coreReady、requiredStages 及各阶段水位，不能因索引失败误判全部状态不可用。
- 四个工作流字段统一走共享 `memoryPolicy`、会话覆盖与作者继承：`syncMode` 默认 `background`，可选 `blocking`；`shortTermTurns` 默认 8、范围 1～32；`autoConsolidate` 默认 true；`statusLink` 默认 false。导入导出和 AI 设置编辑沿用同一归一化路径，不增加第二份运行配置。自动合并压缩是产品唯一合并开关，保存时同步 `merge_memories` 能力；关闭时不提供自动 merge，置顶、来源、历史及不兼容角色/受众/真假范围继续受保护。
- `statusLink` 只协调已经启用的记忆与状态栏 Agent：记忆提取可参考更新前权威状态，状态栏 Agent 接收验证后的提取及同轮证据；两者保留各自模型、工具权限与同一受保护核心事务。状态上下文不是状态变化证据，也不建立另一套数量/余额账本，不会自动启用状态栏 Agent。
- 记忆设置的思考等级复用状态栏 `thinkingLevel` 契约：空值跟随所选供应商，`off` 明确关闭，其余 `minimal` 至 `max` 按模型能力适配。会话覆盖、作者默认和恢复继承保留该值；提取与摘要统一使用，摘要缓存区分有效思考参数，不将内部推理写成事实。
- 完整存档为 snapshot v3；v2 保守兼容，每轮 checkpoint 只存记忆水位和提交引用。恢复/分支依赖规范日志与来源版本，不可按时间盲删仍被 checkpoint/存档引用的记录。向量可以重建，不能把诊断项目快照或作者角色包当完整会话备份。
- 严格 actor 视角无法判定受众时关闭输入通道，普通原文、作者摘要、无受众状态和 Provider 继承上下文不能借旁路注入。默认 cast 调用掌握多角色信息，不能声称它已经隔离了每个被扮演角色的模型认知。
- 记忆工作台默认展示角色档案，可按姓名或别名查找剧情中新建立且没有角色卡的人物，分为记忆、事件、关系、物品。角色筛选是作者查看相关记录的条件，与严格知识视角独立；不能把选择人物当成授予其知情权。物品沿用证据关系与权威场景记录，不虚构数量。档案视图只读，原有审核、编辑与结构化修订保留在“全部记忆”。
- 正常排队/执行进度在聊天中静默，轮询和核心完成后的领域面板刷新继续工作，不替换消息或草稿。异常保留简短“查看记忆”入口；工作台“同步与恢复”展示具体错误、阶段水位、独立派生重试、取消及带范围确认的重建。后台容量允许时可恢复核心失败仍能继续 cast 对话，派生失败不会阻塞核心已就绪的发送。
- 向量仅显式开启；当前适配北京 `qwen3.7-text-embedding-flash`，固定 sqlite-vec 0.1.9。非北京 region/官方国际端点拒绝使用北京价目。原币计费、换算率、provider fingerprint 和删除范围必须随变更保留，清理旧 generation 时不能删除 active/building 或可续建当前失败任务。

本轮实际完成的独立安装验证：在临时目录仅复制 backend `package.json`/`package-lock.json` 后执行 `npm ci --ignore-scripts --no-audit --no-fund`，安装 127 个包；Windows x64、Node 24.16.0 成功加载 sqlite-vec v0.1.9，通过 scoped KNN、先过滤权限再 top-k 和关闭后续扩展加载检查。未触及真实 data/uploads、环境配置或外部付费模型。该结果不覆盖所有发布平台，也不证明真实千问剧情召回质量、延迟或线上计费正确；全量测试与页面验收以主计划执行记录为准。

新数据库不再创建 `town_*` 表及索引，0006 迁移只负责通用任务队列，既有迁移版本和校验标识保持稳定。已有数据库中的历史小镇表、记录和任务不做破坏性清理；默认 worker 不领取旧小镇任务，旧任务不再占用新任务的并发额度，新提交和失败任务重试均拒绝该类型。回归覆盖新库、历史库重复启动、旧 API 404、任务拒绝与额度隔离及保留功能的 HTTP 访问。
