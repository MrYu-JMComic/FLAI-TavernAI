# 角色编辑草稿操作与按钮布局计划

## 目标

修复角色编辑页本地草稿无法移除或移除后再次自动保存的问题，提供清楚的丢弃入口，并统一该页按钮尺寸、对齐与间距。

## 范围

- 复用现有草稿基线、自动保存和角色编辑布局；丢弃草稿恢复到已保存基线，清理本地草稿，不自动重新创建同一草稿。
- 待恢复草稿和当前自动保存草稿均可丢弃；只读和忙碌状态禁止修改。
- 优化角色编辑页标题操作、保存栏和编辑控件的按钮规格，适配用户截图的中等桌面宽度与手机。
- 保留其他任务的修改；不操作用户实际角色数据，不提交或部署。

## 验收标准

1. 自动保存草稿后可丢弃，表单与关联世界书恢复到已保存状态，刷新及定时保存不会复活草稿。
2. 待恢复的旧草稿也可清理，新角色草稿可清空回初始状态；不误提交角色。
3. 959px 桌面视口与手机操作按钮高度统一、文字清晰、无横向溢出。
4. 适用测试和编码检查通过。

## 实现记录

- 当前草稿与待恢复草稿均提供“丢弃草稿”。丢弃恢复已保存表单和世界书选择，清除本地缓存并取消待执行自动保存；未修改的表单不会重新创建草稿。
- 丢弃时清理本地助手草稿接手状态，并忽略晚到的接手响应，避免旧世界书变更再次混入编辑；保留服务端助手对话与历史。
- 桌面主要操作按钮统一为 44px 高度，统一文字、图标与间距；手机顶部和保存按钮使用 40px、草稿按钮使用 36px。调整窄桌面标题、保存栏及手机操作行，移除重复自动保存提示和冲突样式。
- 草稿行为回归测试 5 个文件共 39 项通过。959×930 与 390×844 端到端测试 2 项通过，覆盖丢弃、定时自动保存、刷新、按钮高度及横向溢出；截图人工检查通过。

### 跟进结果

- 复现三个手机宽度下待恢复草稿按钮由 44px 被撑高至 96px。原因是外层列方向弹性布局与内层按钮行均允许换行，浏览器内在尺寸计算将按钮行按两行高度计算，再拉伸并排按钮。此前手机验证仅覆盖当前草稿单按钮状态，已补充待恢复草稿双按钮检查。
- 在 `character-editor-mobile.css` 关闭草稿区域嵌套换行并使用固定紧凑按钮高度；在 `responsive.css` 移除旧的拉伸和 120px 按钮伸缩基准。手机草稿按钮为 36px、顶部和保存按钮为 40px，图标 16px、文字 13px；草稿按钮按内容宽度靠右排列。
- `npx playwright test e2e/character-editor-draft-controls.spec.js` 5 项通过，覆盖 959px 桌面、手机当前草稿及 360/390/412px 待恢复草稿；检查按钮尺寸、排列、提示区高度、页面溢出和丢弃后的定时保存/刷新行为。手机与桌面截图检查通过。
- `npm run build` 通过；最终编码与差异检查通过。本轮仅修改两处样式和既有端到端用例，未重跑后端或完整审核。
- 无剩余阻碍。
