## 背景与目标

用户在与 AI 角色对话过程中，需要保存当前对话进度（类似游戏存档），以便日后恢复到特定对话节点。该功能支持多存档位，允许用户为同一会话创建多个存档、重命名、删除，并随时读取恢复。

### 目标
- 用户可在聊天界面打开存档面板，查看当前会话的所有存档
- 支持创建新存档（自动截取消息快照 + 生成预览文本）
- 支持读取存档（将消息列表恢复到存档时的状态）
- 支持重命名和删除存档
- 存档与用户/会话绑定，保证数据隔离

## 技术方案

### 数据库层

**表结构**（`backend/src/db.js` 第 414 行）：

```sql
CREATE TABLE IF NOT EXISTS saves (
  id TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  name TEXT NOT NULL DEFAULT '',
  snapshot TEXT NOT NULL DEFAULT '{}',   -- JSON: { messages: [...], savedAt: ISO }
  preview TEXT NOT NULL DEFAULT '',       -- 最后一条 assistant 消息摘要（≤120 字）
  created_at TEXT NOT NULL,
  FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_saves_conversation ON saves(conversation_id);
CREATE INDEX IF NOT EXISTS idx_saves_user ON saves(user_id);
```

### 后端（Express + Node 24 + node:sqlite）

| 文件 | 职责 |
|------|------|
| `backend/src/modules/saves.js` | 核心业务逻辑：CRUD + 快照构建 + 读档恢复 |
| `backend/src/modules/savepoint.js` | SQLite SAVEPOINT 事务封装，读档时保证原子性 |
| `backend/src/routes/conversations.js` | 路由挂载 |

**API 端点**：

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/conversations/:id/saves` | 列出当前会话的所有存档 |
| POST | `/api/conversations/:id/saves` | 创建新存档 |
| GET | `/api/saves/:saveId` | 获取单个存档详情（含快照） |
| PUT | `/api/saves/:saveId` | 重命名存档 |
| DELETE | `/api/saves/:saveId` | 删除存档 |
| POST | `/api/saves/:saveId/load` | 读档（恢复消息列表） |

**读档流程**（`loadSave` 函数）：
1. 校验存档归属（用户 + 会话）
2. 在 SAVEPOINT 事务内：
   - 删除目标会话的所有现有消息
   - 从快照中逐条插入消息
   - 更新会话时间戳
3. 返回 `{ conversationId, messageCount }`

| 文件 | 职责 |

| `frontend/src/components/SaveLoadPanel.vue` | 存档面板组件（弹窗形式） |

**前端组件功能**：

- 删除确认（需二次确认）
- 全局 busy 状态管理（防止并发操作）
- 错误重试机制

## 风险评估

| 风险 | 等级 | 状态 | 说明 |
|------|------|------|------|
| 大会话快照体积过大 | 低 | 已缓解 | snapshot 为 JSON 文本，SQLite TEXT 字段无硬性限制；单会话消息量通常有限 |
| 读档时丢失当前对话 | 中 | 已缓解 | 读档前有前端确认流程；后端使用 SAVEPOINT 保证原子回滚 |
| 并发存档/读档冲突 | 低 | 已缓解 | 前端全局 busy 锁 + 后端 SQLite 单写锁 |
| 快照格式向后兼容 | 低 | 已知 | 当前快照仅含 messages 数组，未来扩展（如包含世界书状态）需做迁移 |

2. **快照压缩**：大会话可考虑 gzip 压缩 snapshot 字段
3. **导出/导入**：支持将存档导出为 JSON 文件跨设备迁移

5. **快照扩展**：包含世界书状态、角色设定快照等
