# 任务规划：JJC-20260618-001

- **任务ID：** JJC-20260618-001
- **任务标题：** 对话模板/预设系统增强 — 扩展参数、分类管理与导入导出

### 结论

四个高优先级任务的**核心功能均已实现**，backlog 描述与现有代码基本吻合。其中**对话模板/预设**系统的增强空间最大：

1. **参数覆盖不全：** 当前仅支持 `temperature`, `max_tokens`, `top_p`, `frequency_penalty`, `presence_penalty` 共 5 项，缺少 `min_p`, `typical_p`, `top_k`, `repetition_penalty`, `seed` 等现代 LLM 常用参数
2. **无分类管理：** 预设列表扁平，无分组/标签筛选，预设多时难以管理
3. **无导入导出：** 用户无法分享预设配置（JSON 格式），也无法从社区导入
4. **聊天内切换不便：** 需要离开聊天页面到 PresetView 管理，缺少聊天内的快速选择

## 验收标准

1. **参数扩展：** 创建预设时可设置 `min_p`（0-1）、`typical_p`（0-1）、`top_k`（0-100）、`repetition_penalty`（1.0-2.0）、`seed`（整数或空），这些参数在聊天请求中正确传递
2. **分组管理：** 预设列表按 `group_name` 分组显示，支持按分组折叠/展开，可筛选特定分组
3. **导入导出：** 可将单个预设导出为 JSON 文件，可从 JSON 文件导入预设（含冲突检测：同名时提示覆盖或重命名）
4. **聊天内切换：** 在聊天界面可通过下拉菜单快速切换预设，切换后立即生效
5. **向后兼容：** 现有预设数据无需迁移即可正常工作，新参数均有合理默认值
6. **编码合规：** 所有新增/修改文件均为 UTF-8 编码

## 实现步骤

### 步骤 1：数据库 Schema 扩展
**文件：** `backend/src/db.js`
- 在 `initializeDatabase` 中通过 `ensureColumn` 为 `presets` 表新增：
  - `group_name TEXT NOT NULL DEFAULT '默认'` — 预设分组名
  - `extra_params TEXT NOT NULL DEFAULT '{}'` — JSON 字段，存储 `min_p`, `typical_p`, `top_k`, `repetition_penalty`, `seed` 等扩展参数
- 使用 JSON 扩展字段而非逐一新增列，原因：
  - 减少 schema 迁移复杂度
  - 未来新增参数无需改表结构
  - 与现有 `author_advanced_settings` 等模式一致

### 步骤 2：后端模块扩展
**文件：** `backend/src/modules/presets.js`
- 扩展 `toPreset(row)` 返回 `groupName` 和解析后的 `extraParams` 对象
- 扩展 `normalizePresetPayload(payload)` 校验新参数：
  - `min_p`: 0-1 浮点数，默认 0（禁用）
  - `typical_p`: 0-1 浮点数，默认 1（禁用）
  - `top_k`: 0-100 整数，默认 0（禁用）
  - `repetition_penalty`: 1.0-2.0 浮点数，默认 1.0（禁用）
  - `seed`: 整数或 null
  - `groupName`: 字符串，默认 '默认'
- 新增 `exportPreset(database, userId, presetId)` — 返回可序列化的预设 JSON
- 新增 `importPresets(database, userId, payload)` — 接受 JSON 数组，逐个创建预设，处理同名冲突

### 步骤 3：后端路由扩展
**文件：** `backend/src/routes/presets.js`
- 新增 `GET /:id/export` — 返回预设 JSON（Content-Type: application/json, Content-Disposition: attachment）
- 新增 `POST /import` — 接受 `{ presets: [...], overwrite: boolean }`，批量导入
- 确保导入时校验每个预设的参数合法性

### 步骤 4：校验 Schema 扩展
**文件：** `backend/src/validations/schemas.js`
- 扩展 `createPresetSchema` 和 `updatePresetSchema`，新增可选字段：
  - `groupName` (string, max 50 chars)
  - `extraParams` (object, with validated sub-fields)

### 步骤 5：前端 API 扩展
**文件：** `frontend/src/api.js`
- 新增 `exportPreset(id)` — 下载预设 JSON 文件
- 新增 `importPresets(payload)` — POST 导入请求

### 步骤 6：前端 PresetView 增强
**文件：** `frontend/src/views/PresetView.vue`
- 表单区域新增「高级参数」折叠面板，包含 `min_p`, `typical_p`, `top_k`, `repetition_penalty`, `seed` 输入框
- 预设列表增加分组标题和折叠功能
- 新增分组筛选下拉
- 新增「导出」按钮（每行）和「导入」按钮（列表顶部）
- 导入时弹出确认对话框，显示即将导入的预设列表

## 风险和注意事项

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| `extra_params` JSON 字段在不同 LLM provider 间的参数名不一致 | 中 | 在 provider 调用层做参数映射，忽略 provider 不支持的参数 |
| 导入恶意/畸形 JSON 导致后端崩溃 | 中 | 严格校验每个字段类型和范围，限制单次导入数量（≤20） |
| 聊天内预设切换时正在进行的流式请求参数不一致 | 中 | 切换预设时仅影响下一次请求，不中断当前流 |
| `presets` 表新增列的迁移在已有数据时的行为 | 低 | `ensureColumn` 已有默认值机制，向后兼容 |
| 前端表单复杂度增加影响移动端体验 | 低 | 高级参数默认折叠，移动端仅显示核心参数 |
