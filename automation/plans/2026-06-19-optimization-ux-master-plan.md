## 一、规划目标

本计划将「深度优化方案」与「用户体验流程重新设计方案」整合为一个可持续拆解的活跃总计划。当前任务只创建规划文档，不实施前后端代码、不修改数据库 schema、不安装依赖、不改变运行时 API。

### 核心原则

1. **先体验，后架构**：优先解决用户路径中高频、低风险、可独立验收的体验问题。
2. **小步执行**：每个子项后续都应拆成单独计划和执行报告，避免一次性大改。
3. **不越权执行**：涉及数据库 schema、依赖安装、路由系统、状态管理、TypeScript 迁移等高风险事项，必须单独立项并获得明确批准。
4. **保留现有视觉风格**：体验优化应沿用现有颜色、圆角、间距、按钮、表单、空状态和通知样式。
5. **移动端优先补强**：聊天、消息操作、侧边栏、输入框等高频流程必须覆盖移动端交互。

## 二、阶段一：核心 UX 流程优化

来源：`foamy-honking-micali.md`

目标：优先改进最高频用户路径，降低操作步骤，减少移动端阻力，提升日常对话效率。

### 1. 首页角色导入流程优化

| 项目 | 内容 |
|---|---|
| 目标 | 将角色导入从打断式弹窗改为更顺滑的页面内流程，并强化导入后的下一步动作。 |
| 用户价值 | 用户导入角色时能更快判断文件内容，并选择「直接导入」或「导入并编辑」。 |
| 建议执行方 | 礼部 |
| 涉及区域 | `HomeView.vue` 的角色导入、空状态、主操作区。 |
| DoD | 支持页面内导入预览；显示角色名称、描述、标签等关键信息；提供直接导入和导入并编辑；导入失败有内联错误；原有导入能力不回退。 |
| 验证命令 | `cd frontend && npm run build`; `node scripts/check-encoding.mjs` |
| 风险 | 文件拖拽全页接管可能影响普通点击或浏览器默认行为，需单独验证移动端和桌面端。 |

### 2. 聊天快速模型切换

| 项目 | 内容 |
|---|---|
| 目标 | 在聊天输入区附近提供轻量模型切换入口，减少打开设置抽屉的步骤。 |
| 用户价值 | 高频切换模型时少走设置路径，下一条消息即可生效。 |
| 建议执行方 | 礼部 |
| 涉及区域 | `ChatComposer.vue`、`ChatModelSwitcher.vue`、`ChatView.vue` 的模型选择状态。 |
| DoD | 输入区显示当前模型；点击后可选择可用模型；保存/切换期间有禁用和加载状态；切换不影响历史消息；无可用模型时给出清晰提示。 |
| 验证命令 | `cd frontend && npm run build`; `node scripts/check-encoding.mjs` |
| 风险 | 当前模型来源可能受供应商、预设、会话设置共同影响，实施前需单独确认优先级规则。 |

### 3. 消息操作可访问性改进

| 项目 | 内容 |
|---|---|
| 目标 | 让编辑、删除、复制、分支、swipe 等操作在桌面和移动端都可发现、可操作。 |
| 用户价值 | 移动端不再依赖 hover，长按或显式按钮可稳定触发消息操作。 |
| 建议执行方 | 礼部 |
| 涉及区域 | `ChatMessageItem.vue` 的消息操作区和编辑模式。 |
| DoD | 桌面端保留悬停工具栏；移动端提供长按或显式操作菜单；编辑时自动聚焦；复制失败有反馈；操作忙碌时不可重复触发。 |
| 验证命令 | `cd frontend && npm run build`; `node scripts/check-encoding.mjs` |
| 风险 | 长按、滑动和文本选择容易冲突，需用真实移动视口验证。 |

### 4. 角色表单自动保存草稿

| 项目 | 内容 |
|---|---|
| 目标 | 为角色创建/编辑提供本地草稿保护，减少误关闭或跳转造成的数据丢失。 |
| 用户价值 | 长表单填写更安心，下次进入可恢复未提交内容。 |
| 建议执行方 | 礼部 |
| 涉及区域 | `CharacterFormView.vue` 的表单状态、离开提示和 localStorage 草稿。 |
| DoD | 每 30 秒或关键字段变化后保存草稿；显示保存中/已保存状态；成功提交后清理对应草稿；重新进入时提示恢复；不同角色/新建表单草稿互不覆盖。 |
| 验证命令 | `cd frontend && npm run build`; `node scripts/check-encoding.mjs` |
| 风险 | 草稿中可能包含大量文本或本地图片预览，需限制存储体积并避免保存敏感 API key。 |

## 六、推荐执行顺序

| 顺序 | 任务 | 理由 |
|---|---|---|
| 1 | 首页角色导入流程优化 | 纯前端体验项，用户价值高，风险相对低。 |

| 6 | 聊天虚拟滚动或消息分页专项计划 | 性能收益高，但需要先确认滚动和 API 契约。 |

## 七、通用验收与报告要求

每个后续执行任务都必须满足：

- 不修改 `backend/data`、`backend/uploads`、`.env`、`.env.*`、`node_modules` 或生成构建产物。

- 前端相关任务至少运行 `cd frontend && npm run build`。
- 后端相关任务至少运行 `cd backend && npm test`。
- 所有任务运行 `node scripts/check-encoding.mjs`。
- 写入 `automation/reports/YYYY-MM-DD-topic.md`，说明改动文件、验证结果、残留风险和下一步建议。
- 需要新增依赖、数据库 schema、外部服务、迁移或安全策略变化时，先创建单独计划并等待明确批准。
